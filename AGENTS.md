# AGENTS.md

This file is for code review only. It is read by pull-request reviewers; it is not guidance for an agent running this plugin, and nothing in it applies to a running agent's conversations or tools. Development guidance lives in `README.md` and `docs/development.md`.

## Code Review Rules

This section describes how pull requests in this repository are reviewed, including by automated PR review. Each rule names the priority a violation receives; cases it does not cover are left to the reviewer's judgment. Findings cite the rule number (for example "Review rule G3"). A finding the author shows to be wrong is closed with a reply.

### General rules

- **G1 Baseline (P1).** A PR targets the integration branch named in R1, or one of the exceptions R1 allows, and contains only changes for its stated purpose. Unrelated files, reverts of commits already on the base branch, and leftovers from a wrong base are violations.
- **G2 Concurrency and consistency (P1).** A read-modify-write of the same state is atomic: under one lock or one database transaction, or through an equivalent primitive such as compare-and-swap or code that runs to completion on the single-threaded event loop without awaiting. When a write the operation depends on fails, the code does not acknowledge the message, advance a cursor / offset / watermark, mark the work done, or report success. Auxiliary writes (audit rows, telemetry, metrics) and writes documented as best-effort are not violations when their failure is logged and nothing acknowledges, advances or reports success based on them; turning a durable write into a best-effort one without documenting it is.
- **G3 Safe defaults (P1; P0 when it exposes data or bypasses authentication / authorization).** Authentication, permission, validation and config-loading failures deny or stop rather than continue. A fail-open result is never cached. A change does not widen a permission check or move an error into a less strict class, such as an auth failure into success, a permanent error into a silent drop, or a client error into a retry that hides it. Retries, credential refreshes or fallbacks that the protocol or this repository's documentation prescribes are not a widening. A fail-open path the documentation explicitly approves is not a violation; adding or widening one without documenting it is.
- **G4 Documentation (P1).** A change to an interface, config key, persisted field or invariant updates the matching documentation in the same PR, and the docs do not contradict each other or the code.
- **G5 Test scope (P1 when behavior changes without a test; P2 for thin coverage).** A behavior change comes with a test at the level that would catch a regression. Deleting, skipping or weakening an existing test to make a change pass is P1 unless the PR explains why the test was wrong. Documentation-only PRs need no tests, unless the changed text is executed, extracted by tests, copied byte-for-byte into another product, or hash-pinned — then it is behavior.
- **G6 Secrets (P0).** No credential of any kind — API key, token, password, private key, database DSN with a password, signed URL — appears in code, tests, fixtures, docs, scripts or commit messages. Real values come from the environment or an ignored local file; examples use obvious placeholders.
- **G7 Public repository hygiene (P0).** This repository, its history, its PRs and its published packages are public. Violations: internal or staging hostnames and private IP addresses; cluster, namespace, container-registry, storage-bucket or jump-host names that are not part of a documented public endpoint; names or paths of private repositories; internal ticket or task IDs (a `T` followed by a number, in the form `T<n>` or `T<n>.<m>`); real production identifiers; personal e-mail addresses or real user nicknames; internal planning or incident material. Default endpoints are public HTTPS / WSS domains, or the code fails closed and requires explicit configuration. Loopback addresses (`127.0.0.1`, `localhost`) used on purpose for local development, tests or same-machine IPC are not internal hosts; private-network addresses are. Scanner rules and the test fixtures that need such shapes to prove detection, and lines carrying a documented `redact-allow:<id>` marker, are exempt; real production values in them are not.

### Repository-specific rules

- **R1 Baseline (P1).** Non-urgent PRs are based on and target `pre-release`. A PR to `main` is either the `pre-release` → `main` release PR or a fix that explicitly says it is urgent.
- **R2 Protocol v2 copy (P1).** `docs/client-integration.md` is this plugin's copy of the server-side Protocol v2 contract. A change to wire-format handling (`clawchat_gateway/protocol.py`, `clawchat_gateway/inbound.py`) that does not update it in the same PR is a violation; the server contract wins where they differ.
- **R3 Tracked tests (P1).** `tests/*` is ignored by default. A new test file without its own `!tests/<name>` line in `.gitignore` is never committed, so it is a violation even if the PR reports it passing.
- **R4 Install payload (P1).** Every tracked file is copied into `$HERMES_HOME/plugins/clawchat/` on install. A tracked file that the Hermes install scanner (see `tests/test_install_scan.py`) rates high or critical is a violation. Bundled skills under `skills/` are the place for agent-facing guidance; this file carries only review rules.
- **R5 Tool list (P1).** `plugin.yaml` `provides_tools`, the registrations in `clawchat_gateway/plugin_tools.py` and `docs/reference/tools.md` change together when a `clawchat_*` tool is added, renamed or removed.
